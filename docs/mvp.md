# MVP and V1

Updated: 2026-11-03.

This is the delivery scope, priority and status checklist. [`architecture.md`](architecture.md) owns architecture and security boundaries, and [`AGENTS.md`](../AGENTS.md) owns working rules. Update this file and the architecture doc in the same change when scope, decisions or implementation status changes. A backlog request is not permission to implement it ahead of the current priorities; ask the user before promoting V1 work into MVP.

**Status:** Implemented means code exists and its relevant local/Docker checks passed, not that live deployment is proven. The whole product was last validated on E2B on 2026-11-02, as a client would use it, on the deployed Worker with the real model and real GitHub: see [`experiments/e2b-e2e/`](../experiments/e2b-e2e/README.md). Backlogged means requested, not implemented. Release phases here are separate from the architectural build slices in `architecture.md`: a feature previously recorded under the slice 1 backlog may still be deferred to V1.

## MVP: one working personal cloud coding agent

**Success:** start a session without requiring a repository or branch, optionally choose a base repo, send a task, let the agent edit files and run tests, observe/cancel work, and retrieve the result on a restricted Git branch. Single user, Pi on the server, one E2B sandbox per session, text chat, Anthropic API key. Exercise the backend through HTTP/test clients first; a native app is not an MVP prerequisite.

## Beyond the current MVP/V1 commitment

| Feature           | Status       | Gate                                                                                                                                                         |
| ----------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Multiple users    | Not built    | Real application authentication, server-derived account identity and account isolation; never accept arbitrary client user IDs as credential-store selectors |
| Pi package parity | Out of scope | Extensions don't run unmodified on Pi Durable; `ask_user_question` and `todo` are native tools based on the packages                                         |
| Plannotator       | Deferred     | Revisit when review/annotation is prioritized                                                                                                                |
| Paper MCP         | Deferred     | Until Paper ships a remote MCP                                                                                                                               |
| MCP server        | Not built    | Follow the later architecture slices only when prioritized; not a prerequisite for the personal cloud MVP                                                    |

**Known limits:**

| Limit                                           | Effect                                                                                                                                                                                                                                                            | Resolve                                                     |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `NativeContent.parse` throws on unknown content | Snapshots and history with that entry may fail. Not yet tested                                                                                                                                                                                                    | Before a Pi upgrade or V1 image attachments                 |
| A killed supervisor can leave its child running | The command ends as `lost` with a warning, but the agent could rerun it beside the old one                                                                                                                                                                        | Process groups help on a clean stop. Leave until it happens |
| `github.com` returns 429s to the Worker         | Sign-in retries for about 90 seconds. The Git proxy retries for about 60 seconds, and pushes over 32 MiB get one try. Not yet deployed or measured against real GitHub. Move the proxy to EC2 or DigitalOcean only if this becomes a real problem                 |
| A provider policy refusal stays in context      | The run fails with `refused`, and later messages can be refused too because the blocked message is still in the conversation. A new session clears it. Prompts that look for credentials trigger it, so the test driver runs its secret scan through E2B directly |
| SSE disconnects may log an error                | Log noise that could hide real failures. Not yet confirmed                                                                                                                                                                                                        | Check during the first live run                             |
| Two lifecycle timing tests are load-sensitive   | `lifecycle.test.ts` (keep-alive) and `long-response.test.ts` failed once with the machine's load average near 33, then passed twice. Rerun before investigating                                                                                                   |

**Cleanups with a trigger:**

| Cleanup                         | Problem today                                               | When                                                       |
| ------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| HTTP out of domain code         | `messages.ts` and others return `Response` objects directly | When a non-route caller appears, such as MCP or delegation |
| Direct Worker-to-Thread routing | All session traffic goes through the single `Catalog`       | When parallel sessions show contention                     |
| Shared test harness             | Tests repeat their setup                                    | When it slows new tests                                    |

**Seen live:** a sandbox read `unreachable` briefly, and a message then got a 503 `sandbox_not_ready`. It cleared within 20 seconds, so clients should retry.
