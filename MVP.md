# MVP and V1

Updated: 2026-10-30.

This is the delivery scope, priority and status checklist. [`AGENTS.md`](AGENTS.md) owns architecture, security boundaries and working rules. Update both in the same change when scope, decisions or implementation status changes. A backlog request is not permission to implement it ahead of the current priorities; ask the user before promoting V1 work into MVP.

**Status:** Implemented means code exists and its relevant local/Docker checks passed, not that live deployment is proven. No paid model/Boat end-to-end coding task has been validated. Backlogged means requested, not implemented. Release phases here are separate from the architectural build slices in `AGENTS.md`: a feature previously recorded under the slice 1 backlog may still be deferred to V1.

## MVP: one working personal cloud coding agent

**Success:** start a session without requiring a repository or branch, optionally choose a base repo, send a task, let the agent edit files and run tests, observe/cancel work, and retrieve the result on a restricted Git branch. Single user, Pi on the server, one Boat sandbox per session, text chat, Anthropic API key. Exercise the backend through HTTP/test clients first; a native app is not an MVP prerequisite.

### Immediate focus

1. Fix model error handling so Pi's retries and overflow compaction work and clients see why a run failed.
2. Done: PAT storage, private clone, branch-restricted Git proxy/push, PR tools and approvals. Wire the capability-token refresh into the long-run keep-alive.
3. Minimum lifecycle safeguards. Native auto-compaction is verified.
4. A real end-to-end coding task. Paid validation requires explicit authorization.

Do not expand into the V1 convenience features below while the MVP cannot complete a coding task. Protocol and its tests come first, then backend implementation, then API routes. Keep atomic, tested commits.

## Open items

Moved here from the former `NEXT.md`.

**Paid proofs** (need explicit approval; a PAT, a throwaway repo and a deployed Worker with `PUBLIC_URL`):

- [ ] PAT routes, proxy, push policy and approvals against real GitHub, including whether `Authorization: Basic x-access-token:<PAT>` works for a fine-grained PAT on smart-HTTP.
- [ ] A command over an hour on live Boat, restarting the Thread during it (Cloudflare alarms have a 15-minute wall-time limit; nothing has been tested past a few minutes).
- [ ] A very long single model response against platform limits.
- [ ] Stop and resume a sandbox mid-run; files survive and the session recovers.
- [ ] The real end-to-end task: clone, edit, test, push, plus lost receipts, restart and cancellation.

**Smaller gaps:**

- [ ] The clone at session creation is detached and unreconciled. If that matters, drive it from a first message or a durable job.
- [ ] A crash test for an approval left in `executing`. `unknown` covers the same path; the persisted-then-crash window isn't injected.
- [ ] Pack parsing instead of the post-hoc force-push revert, if the brief window on the session branch ever matters.
- [ ] When fork is built, pass `ttlSeconds` to it (a fork otherwise gets 1 h).

**Known limits:**

| Limit                                           | Effect                                                                                     | Resolve                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `NativeContent.parse` throws on unknown content | Snapshots and history with that entry may fail. Not yet tested                             | Before a Pi upgrade or V1 image attachments                 |
| A killed supervisor can leave its child running | The command ends as `lost` with a warning, but the agent could rerun it beside the old one | Process groups help on a clean stop. Leave until it happens |
| SSE disconnects may log an error                | Log noise that could hide real failures. Not yet confirmed                                 | Check during the first live run                             |

**Cleanups with a trigger:**

| Cleanup                         | Problem today                                                | When                                                       |

| Direct Worker-to-Thread routing | All session traffic goes through the single `SessionCatalog` | When parallel sessions show contention                     |
| Shared test harness             | Tests repeat their setup                                     | When it slows new tests                                    |
